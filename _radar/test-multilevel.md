## 三、公式定界符（写公式前先看这段）

两个渲染环境（网站的 kramdown + MathJax、VS Code 的 KaTeX 预览）脾气不一样，实测下来的结论是：

- **行内公式用 `$x$`**，例如 `$f_c$`、`$\varphi^{\prime\prime}(t_0)$`。
- **独立公式把 `$$` 单独放一行**，公式前后各留一个空行。
- 别用 `\(x\)`、`\[x\]`：VS Code 的插件认，但 kramdown 会把反斜杠吃掉，网站上公式变成裸文本。
- 也别把行内公式写成 `$$x$$`：网站上能渲染，但 KaTeX 系预览（VS Code 内置预览等）只认 `$x$`，
  会把 `$$x$$` 当成行间公式甚至不渲染。

还有几个"公式里不能直接写"的字符（`$...$` 是普通文本，kramdown 会照常处理 markdown）：

| 别写 | 改写为 | 原因 |
| :--- | :--- | :--- |
| `\{` `\}` | `\lbrace` `\rbrace` | kramdown 会把反斜杠吃掉 |
| `\|x\|` | `\lvert x \rvert` | GFM 会把含竖线的整行当表格 |
| `*` | `\ast` | 会被当成强调标记，插进 `<em>`，公式直接废掉 |
| `'` `''` | `\prime` `\prime\prime` | 智能引号会把撇号换成弯引号 |

写完跑一遍规范化脚本最省事：

```powershell
powershell -ExecutionPolicy Bypass -File tools/normalize-math.ps1 -Path "_radar/你的文档.md"
```

它会把上面这些都改好，并顺带删掉正文里多余的一级标题。
